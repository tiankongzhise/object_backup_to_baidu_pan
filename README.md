# object_backup_to_baidu_pan
将对象备份到百度网盘。是item_backuo_simple的v2版本
一、项目背景

本程序预期开发一个备份系统，用于将本地文件和文件夹备份到百度网盘

二、详细流程设计
1 单文件处理流程（同步阶段）
1. 源文件扫描 → 数据库比对 → 文件分类计算 → 源文件Hash计算
   ↓
2. 压缩处理 → 压缩包Hash计算 → 解压验证
   ↓
3. 验证通过 → 删除解压文件 → 进入上传队列
   ↓
4. 异步上传 → 上传成功回调 → 数据库更新 → 删除源文件和压缩包

2 存储路径规范
由config指定压缩文件，解压文件，和上传到百度云盘的保持路径父级目录，压缩文件与解压文件路径需保持在同一个磁盘，否则报错。
然后根据以下规则生成具体的存储路径
压缩目录/YYYYMMDD/源文件夹名/加密密码/文件名.zip
百度云盘指定目录/YYYYMMDD/源文件夹名/加密密码/文件名.zip
解压文件路径只需要生成父级，具体解压文件路径在解压时生成
解压目录/YYYYMMDD/源文件夹名/加密密码/文件名

3.3 资源管理策略
3.3.1 磁盘空间管理

监控阈值：总使用量不超过config指定的大小，默认80GB，计算压缩文件指定目录的所在盘的可用磁盘空间大小。初始化时判断剩余磁盘空间是否够使用，不够直接报错退出。

动态控制：

计算下一个待处理文件所需空间

如果剩余空间不足，等待已上传任务释放空间

空间释放后检查是否满足下一个文件需求

3.3.2 各阶段空间占用估算

阶段1：源文件Hash计算    占用：0
阶段2：压缩处理         占用：压缩包大小
阶段3：解压验证         占用：压缩包大小 + 解压文件大小
阶段4：验证完成         占用：压缩包大小
阶段5：上传完成         占用：0

3.4 异步上传机制

上传任务放入队列，后台线程处理

上传完成触发回调函数

回调处理：更新数据库 + 清理本地文件

支持失败重试和断点续传

五、错误处理和恢复
5.1 异常处理

压缩失败：重试3次后标记为失败

验证失败：删除压缩包，重新压缩

上传失败：加入重试队列，最多重试5次

空间不足：暂停处理，等待空间释放

5.2 恢复机制

定期检查未完成的任务

记录各阶段状态，支持断点续做

清理僵尸进程和临时文件
